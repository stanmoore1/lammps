Checked and found CLEAN (no finding filed):
- ev_tally math of every style matches Bond::ev_tally (src/bond.cpp:178) including the
  newton_bond half/full factors and the 2.0*v_half_acc convention.
- Force/energy expressions of class2, fene, fene/expand, fene/nm, gaussian, gromos,
  harmonic, harmonic/restrain, harmonic/shift, harmonic/shift/cut, mm3, morse,
  nonlinear, quartic, quartic/exp, table all match the CPU formulas term for term.
- Rule 1 (copymode guard in base dtor): every base class has it
  (`if (copymode) return;` or `if (allocated && !copymode)`).
- Rule 2 (virtual allocate): every base header that a kokkos subclass overrides declares
  it virtual; bond_table.h's allocate() is non-virtual but BondTableKokkos does not
  override it, so that is fine.
- Rule 3 (DAT:: per-atom views): the `Kokkos::View<...,DAT::t_kkacc_1d_3::array_layout,
  KKDevice<DeviceType>::value,...> f` idiom is safe because kokkos_type.h defines the
  HOST dual views with LMPDeviceLayout as well (kokkos_type.h:1244, 1323ff), so host and
  device layouts agree.  Only the layout type name is taken from DAT, not the space.
- Explicit template instantiation present at the bottom of every .cpp.
- All device math uses Kokkos:: (sqrt/exp/log/pow/abs).  Only exception noted:
  std::numeric_limits in bond_gaussian_kokkos.cpp (filed, low).
- No alternative logical tokens, no VLAs, no sprintf/printf.
- Callers (VerletKokkos, verlet_kokkos.cpp:162-166/252-256/463-471) do the
  atomKK->sync/modified around bond->compute, so bond styles need not do it themselves.
- BondHybrid::init_style() writes map[0] = has_quartic on the host without a
  k_map.modify_host(); this is SAFE only because coeff()'s pending modify_host flag is
  still set when the first compute() calls k_map.sync_device().  Fragile but not a bug.
- BondHybrid::read_restart does NOT restore map[]/setflag (hybrid coeffs are not stored
  in restart files), so there is no missing modify_host there either.
- BondHybridKokkos::maxbond_all loop (bond_hybrid_kokkos.cpp:85-88) looks wrong but is
  provably >= max(nbondlist[m]) because EXTRA=1000 is always added; NOT a bug.
- src/KOKKOS/Install.sh action() only removes files (mode 0); the KOKKOS package no
  longer supports the legacy make build (Install.sh:757), so the 22 missing action
  lines only affect stale-file cleanup on `make no-kokkos`.  Filed as low/rule.
